## What people will notice

**Groups (phone)**
- Loan interest now builds **month by month**, flat or reducing balance, the
  same way on the phone and the server. It is no longer charged in full on the
  day a loan is given out. Existing loans are recalculated this way: **a loan
  shows less owed early in its term than it did before.**
- A member's repayment clears **their oldest loan first**, as the server always
  has. The confirmation says what the member still owes across all their loans.
- "Social fund" is now the fund **as it stands** everywhere: contributions
  and fines, less welfare paid out. The online report and the phone used to
  mean three different things by it.
- Signing out waits until everything is sent, and says so. Switching to another
  account on the phone now also waits for unsent visits, photos, mentorship
  notes, office changes and group rules.
- A phone restored while a meeting was open now sends what is added to that
  meeting afterwards. Before, those entries never reached the server.
- If a group's history is still loading, starting a meeting asks first:
  starting one would stop the history from ever arriving.
- Recovering an old local archive now works. It keeps a copy of what it
  replaces, and it refuses while anything is unsent.
- Errors read as sentences ("Could not reach IntelliCash. Check your internet
  connection…"), never raw technical text.

**Web console and reports**
- A **share-out done on the web now closes the cycle**, as the phone's
  share-out does, and seals the meeting it was done in. A double click is
  recognised, not paid twice. It is refused while another meeting of the cycle
  is still open, or when nobody has saved in the cycle.
- A closed cycle's report shows what the cycle was worth (before its payout),
  not a loss of about 100%. "Interest earned" no longer counts overpayments.
- The dashboard's "Savings this cycle", the group list, and the group
  statements now agree. So does the repayment rate on the dashboard and on
  the financial reports.
- Labels corrected:
  - the programme report says "this cycle" and "balance", not "all time";
  - insights says "active members" and "held this cycle";
  - the external-loan column says "fund balance".
- The dashboard shows six shortcuts, plus "Show all". Figures fill their row.
  The bottom bar fits however many tabs a group has.
- Intelli-Store and voting are **off** for every programme until an admin
  switches them on (Settings → Modules). Voting exists only in the demo group
  today.
- Member sign-ins are set per group ("Let members sign in", in Edit group
  set-up). All 12 existing member logins keep working.

**Public site**
- `/contact` works on phones; it used to scroll sideways.
- The home page:
  - no longer leaves half the first screen empty on tablets;
  - is about 8,000px shorter on a phone;
  - shows its app gallery as a swipe row on phones.
- New app screenshots, taken from the current app with a fictional demo group
  whose figures add up. They replace screens showing "Demo Test VSLA" and
  KSh 0.
- Branding and images:
  - a light logo on dark backgrounds;
  - a square tab icon;
  - a link-preview image;
  - the 532 KB partner logo is now 7 KB;
  - photos no longer load from Unsplash.
- The illustrative testimonials are **hidden** until real, consented quotes
  replace them (`SHOW_TESTIMONIALS` in `apps/web/src/app/page.tsx`).

**Protection against data loss (operations)**
- `ops/intellicash-backup.sh` (committed; a deploy installs it on the server)
  backs up the database **and uploads**. It checks each copy (integrity, ledger
  rows, checksums) and keeps 14 daily, 8 weekly and 10 deploy copies
  separately. A copy that fails its check stops the deploy.
- A nightly timer, a restore runbook and a script that pulls a copy off the
  server are in `ops/`. The timer is **not installed yet**: see step 9.
- Refusals:
  - the demo seed, the demo reset and the programme-workbook re-import refuse to run against
    a live database;
  - `ensure-schema` refuses `db push` on a database built by migrations;
  - CI now builds the database from the migrations and fails on any drift.
- The data guard also checks that loans, cycles and members keep their fixed
  fields. It allows the legitimate deletion of unused planned meetings.
- A request id reused by another group is refused. (A retry within a group is
  still answered with what was saved.)

## Launch checklist

Each step is done and checked before the next. Steps that change production
need an explicit go-ahead.

1. **Commit** the admin and phone working trees, on a branch. Leave out the
   files that are not part of this release (`scripts/build-manual.py`,
   `facts.py`, `manual_engine.py`, `export-group-access.*`) unless they are
   meant to ship.
2. **Deploy the server**: push to `mine main`, which runs the
   `deploy-production.yml` workflow. In order, it:
   1. takes a data snapshot;
   2. installs the backup script from this commit;
   3. makes a verified backup (the deploy stops here if the backup fails);
   4. deploys and restarts, which runs the 3 migrations;
   5. checks health;
   6. runs the data guard's `verify`;
   7. checks hodi and phinetech.
3. **Backfill meeting statuses once** (rehearsed: 10 meetings phones held but
   never reported closed become SEALED; the data guard still passes):
   ```bash
   cd /var/www/intellicash/app/apps/api
   sudo -u intellicash npx tsx prisma/backfill-phone-meeting-status.ts           # dry run
   sudo -u intellicash npx tsx prisma/backfill-phone-meeting-status.ts --commit
   ```
4. **Check the figures** against the rehearsal:
   - `GET /groups/:id/consistency` for the two groups with money;
   - the admin dashboard.
5. **Switch on modules** where a programme uses them: Settings → Modules.
   Everything is off after the migration.
6. **Phone**: the release bundle is built: `Downloads/IntelliCash-2.6.3-build26.aab`
   (SHA-256 `ad1c668d…c77c6e`, production HTTPS address, no API key). Upload
   it to Play (internal testing first) **after** the server is live. Notes:
   `intellicash_mobile/RELEASE_NOTES_2.6.3.md`.
7. **Tell the field teams** about the three behaviour changes:
   - interest month by month;
   - repayments go to the oldest loan first;
   - sign-out waits for sync.
8. **Watch** the server log and `/health` for the first day.
9. **Install the nightly backup** on the server (`ops/README.md` →
   *Installing*), and schedule `ops/pull-backup.ps1` on a PC for an off-server
   copy. Both need your go-ahead.

**Rollback:** the workflow restores the previous commit automatically if
health checks fail. The migrations only add columns and a table, and the
rehearsal proved `8e97915` runs on the migrated database. So a code rollback
is enough; the database is never restored automatically (`ops/README.md` →
*Restoring*).

## Decisions still open

- **Testimonials**: real, attributed and consented quotes, or leave the
  section hidden.
- **Pricing** ("Free via partner programmes", "Custom"): the code notes it
  must be confirmed with the business before launch.
- **Intelli-Wealth** appears under "Trusted by the programmes…". Confirm it
  belongs there, and that every partner has agreed to the use of its logo.
- **Meeting reminders**: the production server process (`render-server.ts`)
  does not start the reminder loop, so no reminder SMS is sent. Decide
  before turning it on: it sends SMS to members.
- **A cycle closed without a share-out** does not carry its shares forward.
  Only the demo group has one. Decide whether "Close cycle" without a payout
  should be allowed.
- **Off-server backups**: a scheduled pull to a PC (ready), or cloud storage
  (needs credentials).
